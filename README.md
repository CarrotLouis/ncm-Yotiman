# ncm-Yotiman

网易云音乐 PC / BetterNCM 的独立 Yomitan 歌词词典插件。导入自己的词典，**按住 Shift 移动鼠标连续划选，松开 Shift 查词**，也支持 Shift 配合鼠标左键拖选；通过 Yomitan 原生 Anki integration 制卡。

**当前版本 0.1.9。** 源码独立维护，不更新 `jp-furigana` 的现有 PR，不替代振假名插件。仓库名按项目命名使用 `Yotiman`，集成的词典项目名称为 **Yomitan**。

## 功能

- 在 RefinedNowPlayingNext 3.0.2 设置中增加“词典”，优先放在“注音”后；没有注音插件时放在“歌词”后。
- 两处设置同步提供“查词方式”：Shift 划选（默认）、Shift＋左键拖选、两种均可。切换立即生效并保存在独立配置内。
- 开关控制按需查词；独立窗口使用原版 Yomitan 的词典导入、设置和 Anki 功能。
- Shift 划选可以连续跨过多个注音块，实时显示选区，松开后只查询选区内最长的可查词串；相同长度优先靠前的位置，查到后高亮实际匹配范围。整行原文和当前读音独立保留作制卡上下文。
- 仅在网易云位于前台时，新的查词请求才会前置窗口，并把键盘焦点留在歌词页，便于直接再次按 Shift 划选。窗口从属于网易云，随主窗口最小化隐藏，不再持续全局置顶；点击词典窗口仍可正常操作。
- 功能启用后后台预热，并复用已加载的查词页和辅助进程，减少首次等待及逐词查询的重复加载。预热不弹出窗口。
- 同时监听鼠标和指针事件并对一次手势去重，不按 `PointerEvent` 构造函数是否存在来猜测 CEF 的输入方式。使用坐标对应的 DOM Range 处理拖选，必要时以字形矩形定位；拦截同次点击，防止跳转播放进度。
- 捕获整行原文时同时快照当前振假名，读取人工纠音后的当前读音，跳过划掉的旧读音、译文、隐藏括号和逐字高亮副本。
- `{sentence}` 和 `{sentence-furigana}` 制卡时继承快照中的振假名；`{sentence-furigana-plain}` 可用于 Anki 方括号注音。查词词条本身仍使用词典原始释义。
- 同时捕获所选歌词行的中文译文，以及歌曲标题、歌手和网易云链接。译文从 RNP 同一行读取；关闭译文显示时尝试读取该行数据，缺失时留空。制卡上下文随查词历史保存，切歌不会换成其他歌曲的信息。
- 查词页跟随网易云当前明暗状态，精简工具区，不显示 ShareX 附件栏、标题栏图标或剪贴板监控开关。音频高级工作流交由外部工具配置。
- “运行检查”显示组件、歌曲信息和选词流程状态，不记录整首歌词或 Anki 密钥。

## 使用条件

- Windows x64、.NET Framework 4.8、Microsoft Edge WebView2 Runtime。
- 网易云音乐 3.x + BetterNCM/chromatic 1.3.4；播放页适配 RefinedNowPlayingNext 3.0.2。
- 可选：[日语歌词振假名 Plus](https://github.com/CarrotLouis/jp-furigana/tree/standalone)。当前读音直接从页面读取，包含网易云音译、外部网站读音和人工纠音。
- 制卡需要运行 Anki 并安装 AnkiConnect。词典 ZIP 由用户自行导入，不包含在插件中。

## 安装与设置

商店收录后可从 BetterNCM 插件商店安装；也可使用 GitHub Actions 构建产物中的 `.plugin` 手动安装，在合适时重启网易云。不要同时保留多个 `ncm-yotiman` 版本。原生组件由 Windows Actions 编译，商店跟踪自动发布的 `store` 分支 `/plugin`，详细流程和分发信息见[商店维护说明](docs/store.md)。

1. 在播放页“词典”开启功能，点击“打开 Yomitan 设置”。
2. 在 Dictionaries 中导入 Yomitan 格式 ZIP，并确认词典已启用。
3. 默认把鼠标放在词语起点的**原文字面**上，按住 Shift，移动到词语末字，松开 Shift 确认；无需按鼠标。可正反方向划选同一行，注音块不会限制选区。例如“成／り／果てる”可一次选成“成り果てる”。选择“Shift＋左键拖选”或“两种均可”时，也可以按住 Shift 与鼠标左键拖选，松开鼠标确认。
4. 如果制卡，在 Yomitan → Anki 中启用连接，再进入 Configure Anki flashcards，**选牌组、笔记类型，映射字段**。仅打开 Enable Anki integration 还不能制卡。
5. 句子字段可用 `{sentence}` 或 `{sentence-furigana}`，歌曲信息用 `{document-title}`，释义可用 `{glossary}`。字段名取决于自己的笔记类型。

同一次查词保留当时整行文字和读音，之后歌词滚动或切歌不会改变这张卡片的上下文。再次按下 Shift 会立即清除旧选区，重新开始划选，无需先点击其他位置。松开 Shift 才查询，划选中切走窗口、关闭功能或更换查词方式会取消；没有按住 Shift 时不扫描歌词。查询严格限制在同一行、最多 120 字符的选区内，不向选区外补字；没有匹配时保留选区并显示无结果。

### 句子翻译与来源字段

在自己的笔记类型中添加 `SentenceTrans` 等字段，再到本插件内嵌的 Yomitan 设置映射。字段按名称引用，排列顺序不影响映射。浏览器中的 Yomitan 配置独立。

| Anki 字段示例 | Yomitan 映射 | 内容 |
| --- | --- | --- |
| `SentenceTrans` | `{ncm-sentence-translation}` | 所选行的中文译文，缺失时为空 |
| `MiscInfo` | `{document-title}<br>{url}` | 歌名 — 歌手及可点击的网易云歌曲链接 |
| `SentenceFurigana` | `{sentence-furigana-plain}` | 当前整行及人工纠音，适合 Lapis 的 `furigana:` 显示 |
| 自定义字段 | `{ncm-song-title}` / `{ncm-song-artist}` / `{ncm-song-url}` | 单独的歌名、歌手或歌曲地址 |

`ncm-` 标记会加入内嵌 Yomitan 的字段菜单，仅在本插件中提供。已有的释义、单词读音和音频映射继续沿用。插件不自动改变用户映射或 Anki 模板；新增字段需要在自己的卡片背面模板中加入显示引用。仅影响新建或主动更新的笔记，不会批量补写历史卡片，也不会生成翻译或录制句子音频。

## 与早期合并实验版的关系

独立版检测到 `jp-furigana-plus` 的旧词典适配器时，关闭旧适配器，避免同一次拖选打开两次窗口；振假名功能继续由 Plus 管理。已有 PR 跟踪的 `main` / `standalone` 分支不包含这些新改动。

独立版的数据保存在 `<BetterNCM 数据目录>/ncm-yotiman/`，不会删除旧实验版的 profile。首次迁移需要重新导入词典 ZIP；Anki 等设置可先在旧 Yomitan 的 Backup 中导出，再在新窗口导入。安装目录中的组件会复制到固定的数据目录，避免 BetterNCM 重建插件工作目录导致扩展路径失效。

功能默认关闭；启用后延迟预热一个查词页。关闭查词窗口时暂时保留已加载页面，无可见词典窗口且闲置两分钟后退出；关闭功能时立即结束辅助进程。WebView2 和词典会占用额外内存，项目不打包 Electron，也不再携带振假名插件的离线分词词典。

## 开发构建

需要 Node.js 22+、.NET SDK 8，以及 Windows 构建环境。
从 [Yomitan 官方 26.10.12.0 release](https://github.com/yomidevs/yomitan/releases/tag/26.10.12.0) 下载 `yomitan-chrome.zip`，脚本会核验固定 SHA256。

```powershell
npm ci
npm test
powershell -NoProfile -File tools/build-yomitan.ps1 -YomitanArchive C:\Downloads\yomitan-chrome.zip
npm run build
```

生成 `builds/ncm-yotiman-0.1.9.plugin`。构建不会自动安装、重启网易云或发布 Release。
仓库仅包含源码和测试，不包含第三方词典、用户 profile、Anki 卡片和运行时歌词。

## 故障定位

在 BetterNCM 的本插件设置页展开“运行诊断”，点击“运行检查”：

- `helperExists: false`：只安装了源码，未构建原生组件。
- `hasTrack: false`：未取得当前歌曲信息；打开播放页后再试。
- `gesture.hover`：成功确认 Shift 划选的次数（沿用旧诊断字段名）。只使用 Shift 划选时 `down: 0` 正常；`down` 只统计按住鼠标左键开始的拖选。
- `gesture.input`：分别统计实际收到的 `pointerdown`、`mousedown` 和 Shift 按键；`lastInput` 显示最近一次歌词命中的目标类名及修饰键状态，不包含歌词正文。
- `selected: 0`：没有取得有效原文或尚未松开 Shift；划选时应位于原文字面，不要跨译文或相邻行。
- `sent` 增加但没有窗口：查看返回错误；设置页必须能打开，系统也需要 WebView2 Runtime。
- 有查词窗口但没有释义：在独立 Yomitan 设置中检查词典是否已导入并启用。
- 有释义但不能制卡：检查 AnkiConnect、牌组、笔记类型和字段映射；音频字段名必须存在。

## 调研与验证

2026-10-28 检查了 GitHub 仓库搜索、BetterNCM 商店代码及中英文网页索引，未找到覆盖这套离线词典/Yomitan 查词流程的网易云插件；这不表示一定不存在。
相近的 [LyricLens](https://github.com/yoruuuchan/LyricLens) 是 AI 歌词学习浮层，需要 LLM 服务，仓库已于 2026-09-15 归档。

自动测试覆盖当前读音快照、人工纠音、隐藏/重复文本过滤、正反向拖选、原生选择被阻止的场景、独立配置、旧适配器交接与 RNP 菜单位置。原生集成测试使用模拟 AnkiConnect，禁止向真实 Anki 自动添加测试笔记。

Windows 原生测试已验证：

- 明镜 1.4.4 导入 139,462 个词条，约 44 秒；释义保留原样式。
- 在 `pointerdown` / `selectstart` 被拦截的浏览器环境中，旧鼠标事件路径未产生选区，新路径成功选中“戀人”，并取得 `あなた` 的当前读音。
- 原版 Yomitan 添加按钮的 `{sentence}`、`{sentence-furigana}`、`{sentence-furigana-plain}` 均保留人工读音，音频经模拟 AnkiConnect 保存并附加。
- 修复欢迎页被 WebView2 错标为用户操作、覆盖查词页的问题。

可通过 `companion/pointer-smoke/Pointer.csproj` 重跑浏览器拖选回归，通过 `companion/yomitan-smoke/Smoke.csproj` 和 `tests/yomitan-anki-mock.cjs` 重跑原生集成测试。测试数据必须保存在仓库外的专用目录。

完整客户端鼠标交互仍需在实际网易云/RNP 中验证；该版本不宣称已通过所有环境验证。

### 0.1.9：窄菜单查词方式布局

查词方式改为纵向排列、整行点击的选项，长文字可换行，避免 RefinedNowPlayingNext 窄菜单中三个选项互相挤压重叠，保留原来的主题颜色及选中状态。

### 0.1.8：商店分发准备

补充设置页源码与反馈入口、WebView2 SDK 许可和通知；Windows Actions 自动编译并发布商店目录，同时提供固定 Yomitan 版本及本插件的对应源码归档、构建记录和校验和。更换商店封面。

操作查词窗口后，鼠标位于网易云歌词页时按 Shift 可交回焦点并重新划选，松开确认；鼠标位于查词窗口（包括输入框）时按 Shift 继续保留词典焦点。设置窗口或其他程序不会被抢焦点，也不会恢复已经最小化的网易云。原句、译文和读音功能沿用 0.1.7。

### 0.1.7：制卡保留译文与歌曲来源

捕获与选区对应的 RNP 歌词译文，添加四个 `ncm-` 字段标记及设置菜单。将译文、歌曲来源、原句和当前注音保存在查词历史中；生成字段时读取该笔记的上下文，避免异步制卡或返回旧查词记录时混入新歌信息。没有译文时留空，不从邻行或其他歌曲补取。

新增测试覆盖重复歌词的逐行译文、隐藏译文、人工纠音、字段转义、历史快照、空值和菜单去重；真实 Yomitan 的添加按钮已通过模拟 AnkiConnect 验证译文、歌曲信息、原句和注音。

### 0.1.6：查词弹窗保留歌词页键盘焦点

修正 0.1.5 只清除页面选区、但弹窗仍抢走键盘焦点的问题。查词窗口首次显示、再次前置及从隐藏或最小化状态恢复时均不主动夺取焦点，下一次 Shift 可继续由歌词页接收。窗口仍位于网易云上方，点击后可正常使用词典和制卡；主动打开设置时设置窗口照常取得焦点。

原生窗口回归同时检查前景窗口、从属关系和最小化行为，并在加载真实 Yomitan 的集成测试中验证连续查词后的键盘焦点。

### 0.1.5：重新划选时清除旧选区

再次按下 Shift 即清除上一次的高亮和选区，从当前鼠标位置重新开始；查词窗口曾取得焦点、鼠标位置暂时未知时也立即清除旧选区。无需先点击空白处，也不会在没有新选区时重复提交旧词。

### 0.1.4：连续划选与选区内最长匹配

- 默认操作改为按住 Shift 移动鼠标扩展选区，松开才查询。以原文字形定位，不再按 ruby 注音块或自动分词边界限制范围；保留左键拖选模式。
- 在选区内查找最长可行串，包含 Yomitan 原有的词形还原；不从整行补入未选中的字。相同长度优先靠前的位置，整串命中后立即停止，减少额外查询。
- 将实际匹配范围同步回歌词高亮及 Anki 句子位置；保留当前注音和人工纠音。迟到的查询结果不会覆盖新选区，外部返回的范围也不能越过用户选区。
- WebView2 输入测试覆盖跨注音块的“成り果てる”、正反方向、缩放位移、缺少光标定位 API 以及原有鼠标拖选；明镜 1.4.4 实测整串及带前置词的范围均匹配到“成り果てる”，只选“成り”时不越界补全。

### 0.1.3：整词反馈、预热及窗口体验

- 优先对齐注音单元与日语词边界；悬停立即显示原文选区和单元边框，避免从后半个字开始查词。缩放、位移及没有光标定位 API 的场景纳入浏览器回归。
- 后台预热、复用搜索页，热查询不重新导航；缓存请求目录与进程就绪状态，降低逐词查找的通信开销。
- 查词窗口取消全局置顶，改为按请求前置的网易云从属窗口，主窗口最小化时一同隐藏；后台请求不抢焦点。
- 查询界面自动匹配当前明暗主题，增加高 DPI 声明，移除 ShareX 工具栏、标题图标和剪贴板监控界面。查词专用页不启动剪贴板监控。
- 保持现有振假名与人工纠音的制卡继承；新增译文、独立歌名/歌手字段仍处于调研阶段，未实现或更改用户 Anki 配置。

2026-10-28 在隔离测试环境、明镜 1.4.4 词典下，页面预热约 1.0 秒；预热后的原生窗口查询首次 57 ms、再次 49 ms、重复同词 30 ms，均复用同一页面。此计时不含浏览器环境创建、BetterNCM 文件通信和鼠标悬停等待；刚启用功能或闲置退出后仍需要初始化。明暗主题、无工具栏界面和既有注音制卡内容均通过原生回归。

### 0.1.2：Shift 悬停查词

补上与浏览器默认用法一致的 Shift 悬停查词，并作为默认方式。0.1.1 只处理鼠标按下后拖选，因此只按 Shift 移动鼠标时不会触发查词。两处设置同步提供悬停、拖选或两种均可，移除界面上的长篇说明并折叠诊断入口。修正鼠标位于汉字右半边时光标边界可能跳到下一个字的问题。相同位置的鼠标/指针双事件及小幅抖动会合并，Shift 自动重复按键也不会重复遍历歌词。

查词窗口同时改为置顶，并在重复查词时恢复最小化的窗口、再次前置。可用 `companion/window-smoke/Window.csproj` 验证原生窗口层级及恢复行为。

测试覆盖无鼠标按键的悬停、鼠标静止时按 Shift、松开/失焦/关闭取消、定位 API 不可用、人工纠音快照，以及原有拖选。词典、Anki 设置和现有数据目录继续使用。

### 0.1.1：网易云内拖选兼容

针对“歌词已识别、功能已开启，但 `gesture.down` 始终为 0”的反馈，改为同时监听两类输入事件，兼容 CEF 暴露 `PointerEvent` 但只派发鼠标事件的情况。补充 Shift 按键状态跟踪、原生窗口非拖动区域、RNP 行容器及 Plus 已标注行的识别。光标定位 API 不能使用时，按原文字形矩形定位，并在一次手势内缓存测量结果。

浏览器回归覆盖构造函数存在但只发送鼠标事件、双事件去重、修饰键标记缺失、光标定位 API 不可用和未知类名的原生注音布局。设置页支持复制检查结果。0.1.0 的词典、Anki 设置与数据目录继续使用。
